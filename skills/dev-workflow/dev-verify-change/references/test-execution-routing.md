# 测试执行与覆盖率路由

仅在当前仓库或任务涉及对应技术时读取相关小节。用户说明、仓库 `AGENTS.md`、构建配置和 CI 门禁是事实源；本文不设统一阈值。

## 测试入口与发现规则

- 优先使用仓库文档或 CI 已验证的命令，并在报告中记录完整命令
- 新增、修改或迁移测试时，以测试发现配置或实际执行结果判断目录与命名；不能只凭目录名称推断规则
- 临时命令失败时先确认入口参数和 profile，不先修改业务构建配置来迎合命令

## Maven 与 TestNG

- 检查 `pom.xml`、Surefire/Failsafe 配置和仓库文档，确认是否依赖 `suiteXmlFile`、固定 suite XML、profile 或 JVM 参数
- 仓库要求 suite 时优先复用已有 suite，或显式传入 `-DsuiteXmlFile=...`
- 仅存在 `mock` 目录不代表 suite 必然只发现 `mock.*`；需要配置或执行证据

## 覆盖率

- 从任务验收条件、CI/质量门禁和仓库文档确认是否适用及阈值；找不到阈值时只报告观测值，不判定达标
- 适用时优先给出新增/修改可执行行的证据，不用全仓百分比掩盖改动行缺口
- Java/Maven 需要改动行、跨模块聚合或报告可信度诊断时调用 `verify-java-coverage`
- 仓库没有覆盖率框架且任务无覆盖率要求时记录“不适用”；定向测试、静态检查或人工检查已满足本次必需证据时可给出“通过”。覆盖率不适用本身不产生 `VL-*`、受限通过或额外风险授权。
- 门禁要求覆盖率但因环境、依赖或权限无法生成时，不宣称通过；记录限制、替代证据和下一条可执行命令
