# 实现简洁性细则

仅在改动涉及对应维度时使用；仓库明确约定优先于本文的通用阈值。

## 路径、方法与抽象

- 默认保持单一主路径。只有语义、顺序、故障隔离或灰度/回滚确实不同才保留双路径，并说明为何不能统一。
- 同一逻辑至少复用两次，或代表稳定、可命名的概念时再拆方法/抽象；一次性的 `5-10` 行薄包装通常不拆。
- 方法承担多项职责且约 `40-60` 行时评估拆分；超过约 `80` 行原则上必须评估。纯顺序编排且拆分损害可读性时可保留。
- 嵌套持续超过 `2-3` 层且拆分能降低认知负担时，优先使用提前返回或提取稳定概念。
- 新增 helper、结果对象、context 或额外类前，确认它会复用、代表稳定业务概念，或能显著降低主流程复杂度。

## 参数与防御式代码

- 能在使用点获取、计算或从现有对象读取的信息，不跨多层透传。
- 仅当值来自调用方决策、获取代价高或传递能避免重复 I/O/构造时向下传参。
- 方法出现超过 4 个业务参数或多层上下文透传时重新评估接口；不为减少参数数目创建空心 DTO/context。
- 对外部输入、配置、缓存、MQ 和异步回调做必要校验；内部强约束对象优先暴露违约，不层层添加没有真实触发场景的判空、fallback 或默认分支。

## 重复、配置与日志

- 当前改动中相同或高度相似逻辑出现两次及以上时，优先合并条件、复用局部结果或提取公共片段，避免拷贝后小改。
- 不重复已经由上游保证的判空、状态、权限或配置解析，除非中途语义发生变化。
- 删除被统一逻辑覆盖的旧分支、变量和无明确回滚诉求的过渡代码。
- 新增配置开关前确认环境差异、灰度或快速回滚诉求；数值配置已覆盖布尔语义时不再加布尔开关。
- `info` 只记录关键开始/结束、状态变化和低频排障事件；高频循环与逐项细节默认使用 `debug`。

## 注释

- 以读者能理解代码为准，仓库风格决定注释形式，不决定是否省略必要说明。新增或实质修改代码时，分别检查类职责、方法语义与关键逻辑，不能只在交付摘要中解释。
- 类：新增业务服务、执行器、状态持有者等应简述职责和关键边界；名称已完全说明用途的简单 DTO、枚举或工具类无需套模板。
- 方法：新增或实质修改的方法默认都写方法注释，说明用途；有参数、返回值或会抛出/拒绝的错误时，逐个说明参数的业务含义和取值约束（能否为空、单位、取值来源）、返回值含义（含返回空值、空集合各代表什么）、错误的触发条件，以及副作用和调用约束。只有简单取值/赋值和一行直观委托可以不写。不要凭"命名已经说明了"跳过：命名只说明做什么，说不清边界和空值语义。
- 字段与对外数据：新增的数据结构字段、常量和有业务含义的状态，逐个说明含义、取值范围或枚举值、为空时的语义。
- 仓库已有代码的注释稀疏或描述留空，不作为新代码的参照；新代码按本节写全，已有代码不顺手补。
- 以上是各技术栈共同的"写什么、写到什么程度"。用什么格式、哪些语言元素要写，按栈细则：Java 见 `backend-java.md` 第 3 节，前端见 `frontend.md` 第 3 节；仓库自己的注释规范（如前端仓库的编码规范文件）优先于细则里的默认写法。
- 交付前逐个列出本次新增的方法和字段，对照上面几条核对，不凭整体印象判断"注释已够"。
- 方法内部：注释要让没写过这段代码的人审查时能顺着读懂。方法体超过约 10 行或有多个步骤时，按步骤分段，每段前写一行说明这一段做什么、产出什么、为什么这样做（主流程可编号）；非显而易见的分支条件、三元表达式、流式链、键名取值、排序/去重/兜底取值，在上方写业务含义和取值来源。单个赋值、getter 调用这类一眼能看懂的语句不逐行翻译。
- 关键逻辑：在相关位置解释非显而易见的业务规则、分支优先级、兼容行为、超时与取消、熔断与恢复、并发隔离等原因和边界；同一含义集中说明一次，不逐行复述操作。
- 注释只承载帮助理解代码的职责、逻辑及约束。不写需求/方案/开发清单的章节号、版本号、AC/CHG/DEV/TC 编号、审批记录、执行状态或实现过程；追踪信息放开发摘要、执行清单或验证材料。依赖版本仅在确实影响代码行为或兼容边界时注明。
- 修改逻辑时同步核对相邻注释；说明必须与实际实现相符，不夸大保护效果（例如停止等待不等于终止后台任务），不写猜测、过期背景或长篇方案。
- 注释格式（JSDoc、JavaDoc、HTML 标签等）跟随仓库规范；栈特定写法见 `backend-java.md`、`frontend.md`。

例如 `// 影子比对失败不影响远程判定，调用方仍收到远程结果或原异常。` 解释了行为约束；
`// 执行比较` 只重复代码动作；`// 按方案 v4 第 3 节完成 DEV-004` 属于研发追踪信息，不能写入代码。

## 回看清单

- 是否能统一主路径、减少透传参数或删除低价值抽象
- 是否仍有重复判空、条件、分支体、配置读取或中间结果构造
- 类职责、方法语义和关键分支的必要说明是否齐全，注释是否准确、无研发追踪信息且没有逐行翻译；日志是否必要并符合仓库风格
