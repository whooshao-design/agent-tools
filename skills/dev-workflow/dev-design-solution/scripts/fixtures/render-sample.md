# 合成样例：订单导出改为异步任务

> 状态：Draft · 版本：v2 · 日期：2026-10-28 · 主 profile：mechanism-architecture

相关文档：无（本文件是 render_solution.mjs 的测试夹具，内容虚构）。

## 摘要

导出请求改为提交异步任务，前端轮询任务状态后下载文件。

## 1. 背景与目标

### 1.1 现状与问题

同步导出在数据量大时超时。

### 1.2 目标与非目标

| 类型 | 内容 |
|---|---|
| 目标 | 导出不超时 |
| 非目标 | 改变导出格式 |

### 1.3 约束、假设与术语

| 术语 | 含义 |
|---|---|
| 任务 | 一次导出请求 |

## 2. 方案概览

### 2.1 一句话方案与主图

提交任务、后台生成、轮询下载。

```mermaid
sequenceDiagram
    participant 前端
    participant 导出服务
    participant 后台线程
    前端->>导出服务: 【新增】提交导出任务
    导出服务->>后台线程: 【新增】放入队列
    %% 后台线程->>导出服务: 旧的同步回调已删除
    Note over 后台线程: 按提交顺序处理
    后台线程-->>导出服务: 【修改】写入文件并标记完成
    前端->>导出服务: 【新增】轮询任务状态
    导出服务-->>前端: 返回下载地址
```

1. 前端提交导出任务，拿到任务 ID。
2. 导出服务把任务放进队列。
3. 后台线程写文件并把任务标记为完成。
4. 前端按任务 ID 轮询状态。
5. 完成后返回下载地址。

### 2.2 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| DEC-001 | 轮询 | 不引入推送通道 |

### 2.3 为什么这样能成立

任务状态只有一个写入方。

### 2.4 变更总览

| 应用 | 对象 | 变更 | 改动内容 | 详见 |
|---|---|---|---|---|
| 导出服务 | 提交接口 | 新增 | 返回任务 ID | 3.1 |
| 导出服务 | 文件写入 | 修改 | 写完标记完成 | 3.2 |
| 前端 | 下载按钮 | 现有 | 不变 | — |

## 3. 详细设计

### 3.1 任务提交

提交接口只校验参数并入队。

### 3.2 任务执行

```mermaid
flowchart TD
    A[收到任务]:::new --> B{任务已取消}:::new
    B -->|是（跳过）| C[丢弃任务]:::keep
    B -->|否| D[写入文件]:::mod
    D --> E["标记完成"]:::new
    E --> 通知[通知前端]:::new
    classDef new fill:#d9f2d9,stroke:#2e7d32
    classDef mod fill:#ffe9c7,stroke:#e08a00
    classDef keep fill:#eeeeee,stroke:#9e9e9e
```

<!-- render: node-map 丢弃任务=取消处理 -->

| 步骤 | 变更 | 实现位置 |
|---|---|---|
| 收到任务 | 新增 | `ExportWorker.take()` |
| 任务已取消 | 新增 | `ExportWorker.isCancelled()` |
| 取消处理 | 现有 | `ExportWorker.drop()` |
| 写入文件 | 修改 | `ExportWriter.write()` |
| 标记完成 | 新增 | `ExportTask.complete()` |
| 通知前端 | 新增 | `ExportNotifier.push()` |

### 3.3 失败处理

写文件失败时任务标记为失败，前端停止轮询。

```mermaid
sequenceDiagram
    participant 前端
    participant 导出服务
    Note over 前端,导出服务: 失败后不再发起调用
```
