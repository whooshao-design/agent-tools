# 技术方案横切维度

## 使用方法

写正文前逐项判断相关性。相关项写回 `solution.md` 第 3 章对应机制、影响章节或发布章节；本矩阵填在 `traceability.md`，只记录权威位置。N/A 用一句话说明理由，不为无关维度创建空章节。

| 维度 | 触发问题 | 完整的最低条件 | 常见权威位置 |
|---|---|---|---|
| 接口/契约 | 是否改变调用方可见行为、字段或错误语义 | 生产/消费边界、请求响应或事件语义、超时失败明确 | 对应机制或契约小节 |
| 数据/存储 | 是否改变模型、读写、事务或一致性 | 模型、所有权、读写路径、不变量和恢复明确 | 对应机制或数据状态小节 |
| 配置/开关 | 是否新增配置、动态更新、默认值或权限边界 | 来源、默认值、刷新、失败策略和权限明确 | 对应机制与发布门禁 |
| 并发/幂等 | 是否存在重复、乱序、竞态、重入或多副本 | 并发模型、幂等键/锁/版本、冲突结果明确 | 正确性论证 |
| 外部依赖/可靠性 | 是否涉及远程调用、超时、重试、熔断或降级 | 失败分类、重试边界、降级结果和恢复明确 | 失败路径 |
| 兼容/迁移 | 是否存在跨版本、跨环境、历史数据或新旧机制共存 | 版本窗口、顺序、退出条件、残留和回滚限制明确 | 影响与迁移小节 |
| 安全/权限 | 是否涉及凭证、鉴权、敏感数据、越权或审计 | 最小权限、存储/传输、失败安全和审计明确 | 对应机制与风险 |
| 性能/容量 | 是否改变吞吐、延迟、存储、连接或资源上限 | 结论有数据/估算，阈值和扩容/降级策略明确 | 对应机制；必要时专项小节 |
| 可观测性 | 如何发现未生效、错误、降级或数据偏差 | 日志/指标/告警、阈值、通过和回滚信号明确 | 发布、观测与回滚 |
| 发布/回滚 | 是否存在顺序、灰度、数据变更或不可逆动作 | 前置门禁、阶段、通过条件、回滚触发和不可逆边界明确 | 发布章节 |

## 覆盖规则

- `核心机制`、`需求与范围`、`发布/回滚` 和 `追踪` 对正式方案总是相关。
- 相关性矩阵保证“有没有考虑”，正文负责“答案是否正确”，二者不能互相替代。
- 同一失败语义只在一个权威位置定义；风险章节只写残余风险和缓解，不复制机制。
- 未知且会改变方向的内容标为阻塞；无法取得数据但不改变方向时说明估算方法和证据限制。
- 不得用“通用工程实践”替代本方案特有的阈值、版本窗口、状态结果或失败行为。
