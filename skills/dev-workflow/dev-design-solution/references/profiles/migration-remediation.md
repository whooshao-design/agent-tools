# Profile：迁移/整改型

## 适用与核心证明

适用于配置/凭证迁移、数据搬迁、批量治理、依赖升级、跨仓统一改造和旧机制下线。核心要证明：范围可信，所有对象按一致规则从源状态切到目标状态，迁移期间不中断、不误切，最终能确认完成并退出旧机制。

## 第 3 章组织方式

### 3.1 迁移导读（Guide）

- 当前风险和目标状态；
- 对象分类及统一处置原则；
- 迁移阶段、切换点和完成定义；
- 一条代表性对象从现状到目标的正常路径。主图（放在 2.1）默认是现状与目标的前后对照，阶段多于三个且跨系统并存时用阶段图。

### 3.2 分类规则与处置原则

说明范围事实源、分类规则、每类的处置方式、例外和 Unknown。对象盘点清单、检索命令、范围和计数放 `traceability.md` 的证据清单，正文只写分类规则与结论；全称断言附可复跑命令、范围和计数。

### 3.3 目标运行时机制

说明目标配置/数据如何读取、更新、授权、失败和观测；不能只描述搬迁步骤而缺少迁移后的运行机制。

### 3.4 阶段、门禁与切换顺序

说明准备、双轨/兼容、分批切换、验证和旧机制退出；每阶段给出进入、通过和停止条件。

### 3.5 残留、例外、失败与回滚

说明未迁移对象、新增对象、失败对象、残留扫描、不可逆动作、安全残余风险和回滚限制。

### 3.6 保持不变的行为

列出不受整改影响的运行逻辑、环境或调用方及验证方式。

## Reference-level 最低内容

- 源状态、目标状态和分类规则可追踪；
- 目标运行机制、迁移阶段、退出门禁和回滚成立；
- 批量爆炸半径和分批策略明确；
- 个别对象、仓库、文件和 key 的完整处置只在 `traceability.md` 的 CHG 矩阵与证据清单；
- 工期、负责人、commit 规划转后续 DEV 清单。

## 常见误用

- 正文按仓库或文件逐项写"删除/替换"；
- 只有扫描清单，没有目标运行时机制；
- 把 agent 自建扫描结果直接当范围事实源；
- 声称"全部迁移完成"却没有残留扫描和退出条件。
