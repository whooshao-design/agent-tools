# Profile：数据/状态型

## 适用与核心证明

适用于表结构、状态模型、事务边界、缓存一致性、索引、历史数据回填和状态机改造。核心要证明：目标不变量在并发读写和失败恢复下仍成立，历史数据可以被验证地迁移，切换过程不会产生不可解释状态。

## 第 3 章组织方式

### 3.1 数据/状态导读（Guide）

- 当前模型的问题和目标不变量；
- 主要读写参与者和所有权；
- 一条代表性状态转换或读写场景。主图（放在 2.1）默认是状态图，模型结构变化为主时用前后对照；
- 目标模型为什么消除当前问题。

### 3.2 当前与目标模型

使用 schema diff、状态表或必要 ER 图说明实体、字段、基数、状态和所有权；不复制无关完整表结构。

### 3.3 不变量与状态转换

列出合法/非法转换、前置条件、结果、重复执行和终态。涉及状态机时必须能从规则推导代表性场景。

### 3.4 事务、一致性、并发与幂等

说明事务边界、锁/版本/幂等键、缓存策略、冲突结果、失败可见性和恢复方式。

### 3.5 历史数据回填、校验与对账

说明范围、批次、增量写入、重跑、校验口径、差异处置和完成定义。

### 3.6 切换、性能与不可逆边界

说明双写/双读、索引与容量依据、切换顺序、观测、回滚以及 DDL/数据变换的不可逆部分。

### 3.7 保持不变的行为

列出未改变的查询语义、状态、事务或上下游契约。

## Reference-level 最低内容

- 目标不变量、状态转换和事务边界可验证；
- 并发、重复、部分失败和恢复有确定结果；
- 回填、校验、对账和切换闭环；
- DDL/字段/索引精确内容使用表格或 `traceability.md` 证据清单，正文保留理由与语义。

## 常见误用

- 只给 DDL，没有不变量和读写路径；
- 只说"事务保证/加锁"，没有边界和冲突结果；
- 回填只写批处理步骤，没有重跑、校验和对账；
- 把缓存、数据库、接口分成并列百科章节，重复同一一致性规则。
