# Profile：契约演进型

## 适用与核心证明

适用于 HTTP/Dubbo/API、消息事件、SDK、配置格式或跨系统协议变更。核心要证明：生产方和消费方对同一版本语义理解一致，新旧版本在迁移窗口内不会互相破坏，且可以按安全顺序发布和退出旧契约。

## 第 4 章组织方式

### 4.1 契约演进导读（Guide）

- 当前契约的问题和目标语义；
- 生产方、消费方及版本边界；
- 一条代表性新旧交互场景；
- 推荐兼容策略和选择理由。

### 4.2 当前与目标契约差异

用 schema/API diff 或短表说明请求、响应、事件、字段、错误码和行为语义，不用大段散文复述定义。

### 4.3 兼容矩阵与版本窗口

| 生产方版本 | 消费方版本 | 行为 | 是否允许 | 处置 |
|---|---|---|---|---|
| | | | | |

说明向前/向后兼容、默认值、未知字段、重复消息和解析失败。

### 4.4 调用与失败语义

说明超时、重试、幂等、限流、鉴权和错误可见性中实际相关的部分。

### 4.5 发布顺序、调用方迁移与废弃

说明先后顺序、双版本窗口、迁移完成证据、旧版本禁用条件和回滚限制。

### 4.6 保持不变的行为

列出未改变的调用方语义、字段、错误和服务边界。

## Reference-level 最低内容

- 当前/目标语义差异精确，不只列字段；
- 生产方和消费方版本组合可判定；
- 失败语义、发布顺序、迁移和废弃条件闭环；
- 调用方/接口明细进入追踪矩阵，正文按契约机制组织。

## 常见误用

- 只贴新接口定义，不说明旧行为和兼容；
- “向下兼容”没有版本矩阵和失败例；
- 把接口逐个列成 CHG，公共版本策略重复多次；
- 只写发布新版本，不写调用方迁移和旧版本退出。
