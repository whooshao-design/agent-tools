# 图与图表

什么时候该画图、画哪种图型，技术方案按 dev-design-solution 的 `visualization-routing.md`（触发条件、主图、mermaid 稳定子集）。本文只管图放进飞书后怎么显示、怎么写才能出图、图表怎么做。

## 选哪种容器

| 场景 | 默认做法 | 备选 |
|---|---|---|
| 流程、时序、状态、类、ER 等结构图 | ```` ```mermaid ```` 代码块，`publish` 自动建成文本绘图小组件：源码留在文档里，同事能在飞书里直接改 | 画板（节点可拖拽，但不能再按代码改） |
| 时序图参与者超过 6 个或消息超过 20 条 | 拆成几张图，每张只回答一个问题 | — |
| 精细的架构图 | 本地渲染 PNG，宽度 1600px 以上，放在 md 目录里用 `![说明](相对路径)` 引用 | — |
| 3～5 个框的小示意 | 等宽文本代码块：本地、GitLab、飞书三端逐字节一致，中文对齐 | — |

不要用 SVG 当图片上传：飞书按 viewBox 尺寸显示，mermaid 导出的 SVG 通常很小。

## mermaid 在小组件里的写法

小组件内置的 mermaid 不低于 11.10。2026-09-23 在 lexin 实测 22 种写法：flowchart、带 `par` 的时序图、stateDiagram-v2、class、ER、gantt、pie、journey、gitGraph、mindmap、timeline、block、architecture、kanban、radar、treemap、`%%{init}%%` 主题指令、节点里的全角冒号和「→」都能出图。

- 象限图（quadrantChart）、XY 图（xychart）、桑基图（sankey）里有没加引号的中文时不出图。XY 图的中文加双引号已实测能出图；象限图和桑基图加引号的写法没单独实测，先用英文，或发布后到飞书确认。`lint` 把这种写法当错误挡住。
- 不要给流程图的所有标签都加引号：小组件能出图，但建小组件失败退到画板时，全加引号的图会解析失败。只给含特殊字符的标签加引号。
- 全角冒号、「→」、`%%{init}%%` 在小组件里没问题，但 mermaid 8.13（GitLab 等旧版渲染）会报错。文档也要在这些地方看时，避开这些写法。
- 服务端不校验语法：写错也能建块成功，只是不出图。发布前跑 `lint`，它会调用 `check_mermaid.js` 用 mermaid 8.13 和 11 各解析一遍，并把 SVG/PNG 渲染到 `--out` 目录供目视检查。
- 每张图前一句说明它回答什么问题，图后写关键结论；图不能是唯一证据，关键数值和失败语义同时写在正文里。
- 不要用 mermaid.ink、kroki 这类公共渲染服务出图或分享链接，图的源码会发到外网。`lint` 把这类链接当错误挡住。

## 发布后的形态与修改

- `publish` 返回的 `diagrams[].status`：`widget` 正常；`whiteboard` 退到了画板；`code` 退成了代码块；`placeholder_missing` 要人工核对。
- `read` 会把小组件补回成 ```` ```mermaid ````，画板也能读回源码。
- 改图：以本地为准的文档改本地代码块后 `publish`，增量发布会在原位置重建小组件（块 id 会变）。以飞书为准的文档用 `edit --op=replace --block=<小组件块 id> --file=<含新 mermaid 的片段>`；小组件属于受保护块，要用户确认后加 `--allow-protected`。

## 图表

| 场景 | 做法 |
|---|---|
| 数据会持续更新（周报、容量、成本） | 数据放电子表格或多维表格，由脚本经官方 API 更新；图表在源表里建好，手工一次「关联粘贴」进文档，之后改源表即同步。这类图表没有对应的块类型，API 建不了 |
| 方案里的一次性论据图（压测、对比） | 本地用 ECharts 或 matplotlib 渲染 PNG，图下写数据来源、采集时间和环境 |
| 3～8 个分类的占比 | 先用表格；确实要图就用 mermaid `pie` |
| 几个数据点的趋势或对比 | mermaid `xychart`，中文加双引号 |
