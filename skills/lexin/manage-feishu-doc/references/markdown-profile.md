# 飞书方言：本地 Markdown 怎么写

Markdown 是唯一的编写格式。按本文写的文档在本地预览、GitLab 和飞书上都能正常显示；`publish` 和 `edit` 的片段都按这里的规则转换，`lint` 按这里的规则检查。规则都在 lexin 租户实测过（见 `api-facts.md`），没实测的会注明。

## 写法对照

| 写法 | 发布后 |
|---|---|
| frontmatter `title:` 或开头的 `# 标题` | 文档标题，正文里不再重复这个 H1；`edit` 的片段不提取标题 |
| ```` ```mermaid ```` | 文本绘图小组件（只显示图，读者可切到代码）；建不出来退到画板，再不行保留为代码块。写法见 `diagrams.md` |
| `> [!NOTE]`、`[!TIP]`、`[!IMPORTANT]`、`[!WARNING]`、`[!CAUTION]` | 高亮块：📝 蓝、💡 绿、📌 紫、❗ 橙、⛔ 红；内容可含段落、列表、待办和行内格式 |
| `![说明](相对路径)`（也可以写 lark-cli 的 `@./相对路径`） | 上传的图片，说明作图注；图片必须在 md 所在目录或其子目录里 |
| GFM 表格 | 原生表格，任意行数；超过 6 列会横向滚动 |
| `- [ ]`、`- [x]` | 待办，每一项是一个独立的块 |
| 有序列表 | 有序列表；**起始编号不保留**，`3.` 开头的列表发布后从 1 编号。步骤之间夹代码块时，把代码块缩进到上一步下面，否则后面的步骤从 1 重排 |
| ```` ```bash ```` 等围栏代码块 | 代码块，保留语言 |
| 4 个空格缩进的代码块 | 不被识别为代码，里面的 `<` 会被当成正文转义；一律用围栏 |
| `$E=mc^2$` | 行内公式 |
| 有意写的 DocxXML 标签（`<grid>` 分栏、带 `colspan` 的 `<table>`、`<callout>`） | 原样交给 docs_ai；标签里的 Markdown 不解析，行内格式写成 `<b>`、`<code>`、`<a href>` |
| `List<String>` 这类正文里的尖括号 | 自动转义，照常显示；代码里的不动 |
| `<!-- 注释 -->` | 去掉（飞书不保留注释），给出本地警告 |
| `[文字](#标题)` 页内链接 | 只剩文字，给出本地警告；需要跳转时发布后用 `link-plan` 补 |
| `[文字](./other.md)` 本地文件链接 | 失效，`lint` 警告；换成飞书文档或网页链接 |
| `<details>`、`<div>`、`<sup>` 等 HTML 标签 | 按文字显示，`lint` 警告；改成 Markdown 写法 |

## Markdown 写不出来的

- @人、@文档：Markdown 没有写法；而且经 API 写入的 @人不会通知对方（官方文档）。行动项写「负责人 + 日期」，发布后在飞书里 @ 或在评论里提醒。
- 嵌入的电子表格、多维表格、附件、同步块、任务：只能在飞书里插入。`edit` 替换或删除含这些块的范围会先阻断。
- 随数据更新的图表：见 `diagrams.md`「图表」。
- 文字颜色和背景色：没有 Markdown 写法（未实测 DocxXML 的颜色属性）。颜色规则见 `authoring-rules.md`。

## 特殊字符

- `$`：一对 `$` 夹着紧挨的非空白内容会变成公式，`lint` 对夹着中文的情况给警告；字面的 `$` 写成 `\$`。`$100 到 $200` 这种后一个 `$` 紧挨数字的不受影响（实测保持原样）。
- `<`：正文里形如标签的会被自动转义；代码里的不动。
- 从飞书读出来的 Markdown 已经转义过（`\[`、`\|`、`\\`），拿去回写时不要反转义。
- 乱码字符 U+FFFD（编码转换损坏）会被 `lint` 挡住，先修原文。

## HTML 内容怎么发

HTML 不作为编写格式：docs_ai 不接受 HTML，convert 只产出基础块且丢掉内联 `<svg>`。已有的 HTML 先转成 Markdown：

1. 用 markitdown MCP 的 `convert_to_markdown`，参数 `file:///<HTML 绝对路径>`，结果存成 `.md`，和 HTML 引用的图片放在同一目录。
2. 按实测（2026-09-23）补回转换丢掉的东西：
   - 标题、加粗、链接、有序和无序列表、行内代码、表格、`<img>` 都能保留（图片变成 `![alt](相对路径)`）。
   - 代码块丢了语言标记，补上。
   - `<div>` 做的提示框变成普通段落，改成 `> [!NOTE]` 等写法。
   - `<details>` 折叠被展平成正文，按需要保留或删掉。
   - `<svg>` 只剩里面的文字：把 svg 另存成文件，按 `diagrams.md` 改画成 mermaid，或导出宽度 1600px 以上的 PNG。
3. `lint` 通过后再 `publish`。

交互式 HTML（`<html5-block>` 这类小组件）只适合演示，不走这个流程。

## 发布前检查

`publish` 和 `edit` 写飞书之前都会做这些检查，不通过就报 `PUBLISH_PRECHECK_FAILED`，不写飞书：

- 图片不在文档目录内、图片不存在、data URI 图片、图片路径无法解码；
- 代码块没闭合；写了 `<whiteboard>`（会解析失败并被整块丢弃）；
- `lint` 的错误级规则：象限图、XY 图、桑基图里的中文没加引号，引用公共渲染服务，乱码字符。

`lint` 的警告级规则只提示、不阻断，发布时出现在 `localWarnings` 里，带行号。完整规则见 `authoring-rules.md`「写前检查」。
