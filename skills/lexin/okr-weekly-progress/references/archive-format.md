# 周报汇总格式

周报汇总是评审对象，也是 `okr_weekly.mjs write` 的唯一输入。write 只认第 2 节的 KR 小节，其余小节永远不会写进乐空间。

## 1. 文件头

```markdown
# 周工作汇总 2026-10-12 ~ 10-16
<!-- okr-weekly: {"goal_mid":49548,"period_id":26,"window_start":"2026-10-11T16:00:00.000Z"} -->

时间窗：…（北京时间）。来源：飞书「周工作汇报 …」、本机会话 N 个、提交 M 个；按乐空间 OKR 归类。来源缺失：…（没有就写「无」）。

来源缩写：飞=飞书周报，会=会话 ID 前 8 位，提=commit。
```

`okr-weekly` 注释原样取 collect 输出的 `meta`（`goal_mid`、`period_id`、`window_start`）；write 按其中的 `window_start` 判断「本周已发布」，所以周一补写上周的周报也不会判错。任何来源 `status` 不是 `ok`（周报缺失或歧义、登录失效、会话解析失败）都要写进「来源缺失」，并附 collect 给出的原因。

## 2. KR 小节（可写）

每个 KR 一个二级标题，标题前缀必须原样取 collect 输出里的 `heading`，后接 KR 简称：

```markdown
## O1-KR1 `262338` 米霍克、特征平台迭代优化升级

本周工作

1. **人审中台化（印尼）**
   1. 全链路验证通过：修复回调、网关鉴权、连接超时三个问题（飞）
   2. 排查人审转人工失败与人审通过后卡放款（飞、会 580d9572）
2. **线上问题支持**
   1. P00000078 流水只见乐包 2284：预热节点不在 Mock 范围（会 6b6a1bed）
   2. 乐包 3605 旁路状态未更新导致临时版本删不掉（会 38d55653）
3. **乐包规则差异对比**：调研 phabricator 对接，推动乐效提 TAPD 需求（飞、提 1b6f31b57）

下周工作

1. **流程异常告警**
   1. 梳理告警场景，确认未上线流程的负责人获取方式（飞·待办）
2. ……（会，推断）
```

分两层组织：

- 父级是主题，用粗体写：一个项目或需求（如「人审中台化」「server_strategy_decision_java 下线」），或一类工作（「线上问题支持」「工具建设」）。同一主题的事项必须合并到同一个父级下，不要平铺。
- 子级是具体事项，缩进 3 个空格的编号列表，每条以来源结尾；父级本身不写来源。
- 主题下只有一个事项时，写成一行「**主题**：事项（来源）」，不拆子级。
- 父级按重要性排序：重点项目在前，日常支持类（线上问题支持、答疑）在后。最多两层，不再往下嵌套。

- 本周没有归到该 KR 的工作时，保留标题，正文写「本周无」；只有「本周无」的小节 write 不会写入。
- collect 里 `publishedThisWeek` 为 true 的 KR，在标题下第一行写 `> 本周已发布，默认跳过`。write 会跳过带这行的小节；用户要追加时删掉这行即可。
- 每个子级（或单行主题）以括号来源结尾，多来源用顿号分隔；「下周工作」里由未完成事项推断的条目标「推断」，来自飞书待办的标「飞·待办」。
- 只用编号列表（含一层嵌套）、粗体、行内代码和表格，不写链接和 HTML，乐空间会过滤掉。

## 3. 其他小节（不写）

依次是：

```markdown
## 待归类

1. 反欺诈排查系统分单逻辑优化……（飞）——理由：不属于米霍克/特征平台，三个 KR 都不贴切。

## 已排除

1. 会 a7678cf2：VPS xray 通道排查——个人环境，非工作。

## 需脱敏提示

- 飞书原文含订单号、用户 uid，正文已去掉。
```

「待归类」每条写明理由；「已排除」列出所有没进正文的会话和提交及原因，保证完整呈现；「需脱敏提示」列出已去掉或仍需用户确认的敏感信息，没有就写「无」。
