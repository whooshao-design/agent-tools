# 周报汇总格式

周报汇总是评审对象，也是 `okr_weekly.mjs write` 的唯一输入。write 只认第 2 节的 KR 小节，其余小节永远不会写进乐空间。

## 1. 文件头

```markdown
# 周工作汇总 2026-10-12 ~ 10-16
<!-- okr-weekly: {"goal_mid":49548,"period_id":26,"window_start":"2026-10-11T16:00:00.000Z"} -->

时间窗：…（北京时间）。来源：飞书「周工作汇报 …」、本机会话 N 个、提交 M 个；按乐空间 OKR 归类。来源缺失：…（没有就写「无」）。

来源缩写：飞=飞书周报，会=会话 ID 前 8 位，提=commit。
```

`okr-weekly` 注释原样取 collect 输出的 `meta`（`goal_mid`、`period_id`、`window_start`）；write 按其中的 `window_start` 判断「本周已发布」，所以周一补写上周的周报也不会判错。任何来源 `status` 不是 `ok`（周报缺失或歧义、登录失效、会话解析失败）都要写进「来源缺失」，并附 collect 给出的原因。

## 2. KR 小节（可写）

KR 小节是给领导看的：只写进度和收益，不写实现（类名、接口名、配置 key、评审单号、commit、方案细节都不写）。每个 KR 一个二级标题，标题前缀必须原样取 collect 输出里的 `heading`，后接 KR 简称：

```markdown
## O1-KR2 `262546` 米霍克&流程引擎迭代优化

1. **乐包复制支持含实时查询字段的乐包**

   | 需求确认 | 10-16 | 10-19 | 已完成 | |
   | 方案设计 | 10-19 | 10-19 | 已完成 | |
   | 代码开发 | 10-20 | 10-21 | 已完成 | |
   | 测试验证 | 10-20 | 10-21 | 已完成 | |

2. **旁路缓存降低 Redis 查询次数**

   | 阶段 | 开始 | 结束 | 进度 | 补充说明 |

   | 需求确认 | 10-20 | 10-21 | 已完成 | |
   | 方案设计 | 10-21 | | 进行中 | |
   | 代码开发 | 待定 | | 未开始 | |
```

事项按类型选写法：

- 需求类（业务需求、技术需求，有完整生命周期）：粗体事项名作为一级编号，下面一张阶段表，表格缩进 3 个空格。
  - 阶段固定五行：需求确认、方案设计、代码开发、测试验证、上线验证；未开始的也保留。
  - 「进度」只用：已完成、进行中、未开始、阻塞。不写百分比。
  - 「开始」「结束」写 `MM-DD`，只填素材里能查到的日期：先沿用往期汇总（`archive.previous`）同一事项表里已有的日期，再用飞书周报、会话提问时间、提交时间和 `sources.requirements` 里各阶段文档的最早、最晚日期；未开始的阶段只有飞书写了计划才填预计日期，否则写「待定」；进行中的阶段「结束」留空；早于素材、查不到日期的已完成阶段写「—」。
  - 「补充说明」只写阻塞点、依赖或待谁确认，最多一句，没有就留空。
  - 技术需求（性能优化、架构下线、迁移）在表下加一行「收益：预期 …；实际 …」。预期只用需求或方案文档里写过的指标（`sources.requirements` 给出需求的 `summary` 路径），没有就写定性描述；实际在上线并有数据之前写「上线后统计」。
- 排查、支持、协调、联调收尾等没有生命周期的事项：一行「**事项**：结论或当前状态」，只写结论，一句话。
- 排序：需求类在前（按重要性），单行事项在后。
- 「下周工作」只列一级事项，每件一行「**事项**：下一步」；表里已体现的不展开。

其他约定：

- 本周没有归到该 KR 的工作时，保留标题，正文写「本周无」；只有「本周无」的小节 write 不会写入。
- collect 里 `publishedThisWeek` 为 true 的 KR，在标题下第一行写 `> 本周已发布，默认跳过`。write 会跳过带这行的小节；用户要追加时删掉这行即可。
- KR 小节里不写来源标注，来源统一放到第 3 节「来源对照」。
- 只用编号列表、粗体和表格，不写链接、行内代码和 HTML，乐空间会过滤掉链接和 HTML。

## 3. 其他小节（不写）

依次是：

```markdown
## 待归类

1. SLA 指标数据表性能优化：已定联合索引与数据清理方案（飞）——理由：不属于米霍克/流程引擎，三个 KR 都不贴切。

## 已排除

1. 会 a7678cf2：VPS xray 通道排查——个人环境，非工作。

## 来源对照

1. O1-KR2 乐包复制支持含实时查询字段的乐包：飞、会 6c467d78、01a15cf4，提 8b0505b1d
2. O1-KR2 Redis 告警排查：飞、会 01a157d5

## 需脱敏提示

- 飞书原文含订单号、用户 uid，正文已去掉。
```

「待归类」每条一句话并写明理由，不列 commit 清单；「来源对照」按 KR 小节里的事项逐条列出来源，阶段日期是推断的在此注明；「已排除」列出所有没进正文的会话和提交及原因，保证完整呈现；「需脱敏提示」列出已去掉或仍需用户确认的敏感信息，没有就写「无」。
