# 轻档交接与验收

适用于日常需求梳理、内容整理、方案、测试与代码的跨模型协作：主会话组装交接、核对结果、决定收敛；生成者产出；另一模型检查。已接入正式开发或评审流程的部分仍按那套流程走，本清单不产生审批记录。

## 每次交接带什么

主会话在派发前组装下面这份材料，正文一页以内，长内容给路径和章节引用。后端拿到的必须是材料本身，不能只给上一轮结论的摘要。

| 内容 | 最小要求 |
| --- | --- |
| 目标与边界 | task、环节、目标、非目标、允许路径/工具、超时 |
| 当前材料 | 原始需求及来源、当前产物路径与修订标记；评审期间材料不变 |
| 已确认事实 | 用户决定、约束、依赖及来源；没证据的判断不写成事实 |
| 假设与未决问题 | 分开列假设、冲突、待确认项及影响；没有就写「无」 |
| 本轮任务与验收 | 要生成、修订还是检查什么；从下表取对应环节的检查项，说明完成信号 |
| 旧问题与修订回应 | 问题 ID、位置、影响、状态；修订方逐条说明改在哪或为何保留；首轮写「无」 |
| 参与者与回交 | 全部生成者后端及已知实际模型、上一轮评审者；要求回交结果、证据、未解决项和限制，禁止再次委派 |

后端先确认能读到材料，再指出冲突或缺失。输入不足以下判断时，主会话补材料再继续，不替用户做决定。评审轮换时旧问题和修订回应一起带过去，新评审者既找新问题，也逐条核对旧问题是否关闭。

## 各环节查什么

格式、路径、语法、构建、测试这类能机器验的交给机器；逻辑、完整性、可读性交给评审模型；主会话核对证据后决定交回还是修订。下表是最小项，按实际风险加。

| 环节 | 最小检查项 |
| --- | --- |
| `requirement-clarify` | 覆盖用户要点；事实/假设/未决项分离；边界、异常与验收信号明确 |
| `requirement-review` | 不遗漏原始诉求；冲突、依赖与异常有处置；验收可观察且旧问题逐条闭环 |
| `content-organize` | 来源语义和关键要点保留；无擅自结论；层次清楚、重复可删、术语一致 |
| `solution-design` | 对应需求与约束；关键选择说明理由；接口/状态/失败处理及验证路径足以实施 |
| `solution-review` | 需求覆盖且设计自洽；识别遗漏及失败后果；可实施、可验证，旧问题未被摘要掩盖 |
| `testcase-generate` | 关联需求和验收；覆盖正常、边界和失败；前置、操作与预期足以执行 |
| `testcase-review` | 检查漏测风险；预期可判定且与需求一致；合并无区分度重复项并复核旧问题 |
| `code-build` | 完成限定行为且写集符合任务；沿用现有模式；相关构建/测试验证成功与失败路径 |
| `code-review` | 基于实际代码和差异给证据；检查正确性及相关安全/稳定性风险；核对旧问题及验证缺口 |
| `quick-check` | 只做快速检查：明显矛盾、要点缺漏、结构和术语；不替代完整评审 |
| `verify-execute` | 执行约定命令；记录实际结果及失败原因；区分未执行、失败和通过 |

## 选模与登记

1. 先核对生成者。已有产物按对应 generate 环节逐个 `--record BACKEND` 补录；纯用户手写的产物没有生成者记录，来源不明先查清。
2. `pick_agent.py <环节> --task <ID>` 只预览，不占轮次。核对候选可用后按输出模板派发，prompt 用 argv 或输入文件传，不直接 eval。
3. 什么算参与：生成或修订有实质产出，或失败但改了东西，登记生成者；评审拿到有效结论（含要求修订）登记评审者；验证有实际执行结果（含失败）登记。只预览、启动前失败、取消的不登记。
4. 登记带上运行返回的模型 ID：`--record <后端> --actual-model <ID>`。拿不到就省略，记录标 `model_basis=configured`。
5. `--exclude` 只管当次不可用的候选。脚本自动排除该产物的历史生成者和同名模型；别名、配置变更和没登记的参与者要主会话自己核对。当前模型和实测模型不一致时脚本会提示，按本任务检查项做一次受控试运行确认即可。
6. 修订默认沿用最近的生成者。连续两轮无改善或它不可用时，主会话写明原因，`--replace-producer '原因'` 预览接替者，参与后同样登记。换人后旧生成者仍排除，没有合格评审者时停下来说明。

示例（后端为示意，第一条不写历史）：

```bash
python3 /home/joney/projects/ai/agent-tools/skills/common/build-codeagent/scripts/pick_agent.py solution-design --task routing-demo --json
# 主会话实际派发；有实质产出后再登记
python3 /home/joney/projects/ai/agent-tools/skills/common/build-codeagent/scripts/pick_agent.py solution-design --task routing-demo --record claude-vps --actual-model claude-opus-5
python3 /home/joney/projects/ai/agent-tools/skills/common/build-codeagent/scripts/pick_agent.py solution-review --task routing-demo --material '/tmp/review materials' --json
```

同 task 的选择、调用、登记串行。修订沿用 task，另一份同类产物另建 task。记录文件有损坏行时脚本停止并报行号，保留原件核实，不要清空。

## 什么时候停、怎么交回

- 本轮检查项满足、实质问题都已解决或由用户决定了怎么处理、旧问题逐条有证据，才交回。「没有新发现」不等于收敛。
- 按未解决问题、修订回应和实际验证判断有没有改善。连续两轮没关闭实质问题或没补上关键证据就暂停，说明卡点，决定补材料、换生成者还是交给用户。不换评审者刷通过。
- 输入不足、证据冲突、没有合格候选或权限边界满足不了时，停止依赖它的工作并说明恢复条件，保留已有结果和未解决项。
- 回交内容：产物路径、本轮有效修改、检查结果、参与后端与实际模型、未解决项与限制。质量状态三选一：可交回 / 需修订 / 材料不足。
- 试运行时记录信息丢失、有效发现、修订代价和耗时，有新证据再调候选。
