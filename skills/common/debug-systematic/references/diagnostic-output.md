# 复杂故障分析报告的组织与呈现

用于需要综合解释故障机制、业务影响和处置取舍的分析报告。它不是排查类 skill 的通用输出协议；日志检索、看板解读、构建修复等任务使用各自的简短交付格式。
这里只约定报告的表达方式；取证范围、停止条件、只读约束和修复授权仍以调用方 skill 与用户请求为准，不为填满报告扩大查询。

## 何时使用

- 用户明确要求故障复盘、完整根因报告或图片式故障总结时使用。
- 未明确要求报告时，仅在简短结论难以解释“为什么发生、影响谁、如何处置”，需要串联日志、指标、代码、配置/变更等证据说明故障机制与影响时使用。
- 未明确要求上述报告时，单一代码 bug、编译/测试失败、日志查找、服务器快检、指标巡检和看板结构说明不适用。实例多、日志多、错误多或使用了多个工具，本身都不构成使用理由。
- 一个任务只由负责综合分析的主流程整理报告；日志、指标等取证 skill 提供证据和限制，不各自产出一份根因报告。
- 证据不足不阻止交付阶段性结论，但首句须明确“尚未确认根因”，接着给已确认现象、主要假设、缺失证据和能区分假设的最小检查。

## 报告的阅读顺序

以下模块按证据和阅读收益选择，不是必须填满的表单。没有关键量化对比可省略数字区；没有可靠事件序列可省略时间线；简单机制用一段文字，无需画根因链。
只有一个原因就写一个，不凑齐卡片、阶段或优化建议。决定结论可信度的证据缺口仍需明确，不能随模块一起省略。

### 1. 标题与结论

标题写应用/对象和问题。紧接着注明环境、集群/实例范围、绝对时间窗与时区、数据截至时间。
状态分别写清：根因已确认/待确认；故障持续/恢复待验证/已验证恢复。排查完成不代表故障恢复。

首段用 1–3 句说明原因或当前判定、实际业务影响、最优先的动作；决定结论可信度的缺口紧跟结论。
不要先按工具调用顺序汇报过程，也不要把异常堆栈或连接池耗尽等症状直接当作根因。

### 2. 关键数字

挑出最能支撑判断的 2–4 个数字；不足时少放。Markdown 用紧凑表格，HTML 可用指标卡片。
每项带单位、窗口、对象范围及必要基线；比例保留分子/分母或统计口径，近似值明确标注。
区分日志行、异常事件、唯一请求、受影响业务量；单 Pod 数量不能写成集群总量，样本占比不能写成全量占比。
配置缺失时，只有核对运行版本、覆盖来源和默认值后才能称为实际生效值，否则写“代码默认值，运行时待核验”。

### 3. 根因与影响链

可按“触发事件 → 放大机制 → 瓶颈/失效 → 可观察后果”组织，只使用已有证据支持的环节。
并列因素可以并排展示，不强行连成因果箭头；待验证环节写“假设”，图中用虚线且说明缺什么证据。
简单关系用文字或 Mermaid 即可，每个关键因果关系引用对应证据。

单独说明影响边界：哪些请求、业务、实例受影响，哪些已验证未受影响，哪些尚未检查。
异常被 catch 只能说明该代码路径处理了异常；“主流程无影响”还需要返回结果、业务流水或其他运行证据。

### 4. 时间线与关键证据

时间线建议列为“时间（含时区）｜事件/观察｜来源”；区分日志时间、采样时间和查询时间。
把任务、流量、配置、发布变化与首错、峰值、恢复时间对齐；只记录取到的事件，不用查询时间代替首次发生时间。
时间重合属于相关证据，不能单独证明发布或任务是原因；当前缓存/配置也不能直接代表故障时状态。

证据建议列为“编号｜观察与口径｜支持/限制的判断｜来源”，正文用 E1、E2 等引用，避免重复原始日志。
来源按实际使用保留日志文件/traceId、监控查询与窗口、发布记录、源码路径与行号；涉及线上代码时注明制品/版本是否核验。
排除项写出依据和覆盖范围：只查部分日志不能写“无错误”，缺少发布记录不能写“非版本引起”。
查询失败、截断、采样和未查实例直接写在相关判断旁，不能隐藏在附录，也不能显示为绿色正常。

### 5. 处置建议与验证

按适用性区分立即止血、短期修复、后续优化；没有必要的阶段可省略，不为凑层级添加工作。

| 优先级/阶段 | 动作及目标 | 执行方/状态 | 前提与风险 | 验证方式 |
|---|---|---|---|---|
| 按证据填写 | 改哪个对象、解决链条哪一环 | 建议/已执行/待授权；执行方未知则说明 | 配置生效条件、负载或兼容风险 | 在什么窗口观察什么指标或业务结果 |

建议参数要有容量或运行证据，不照抄历史案例值；无法确定时给验证方法。
“已执行”只用于实际完成的动作，“已恢复”只用于已有恢复验证的状态；本地测试通过不能代替线上恢复。
建议本身不授权修改配置、发布、重启或通知他人。保留调用方 skill 要求的修复命令、结果和未覆盖项。

## 文件与视觉呈现

- 需要文件时默认本地 Markdown；用户指定路径优先，其次调用方 skill 的产物目录，否则使用 `/home/joney/docs/diagnostics/`。文件名含对象与日期，避免覆盖历史报告。
- 用户要求图片式排版、HTML，或复杂时间线/关系图确有阅读收益时，可交付本地自包含 HTML 作为唯一主报告；不默认再交付一份相同内容的 Markdown，不上传外部服务。
- HTML 布局可参考：顶栏对象/时间/状态 → 结论横栏 → 指标卡片 → 根因链 → 时间线与证据双栏 → 处置建议；窄屏改为单列，证据保持可读可定位。
- 颜色辅助区分异常、待验证和已验证状态，同时保留文字标识；不依赖颜色传达结论，不把“未查到数据”标成正常。
- 不为排版生成装饰图片或把正文截图化，不强制采用 HTML；事实、数字和代码标识应可复制，敏感信息按调用方规则脱敏。

## 交付前检查

能否从结论找到支持它的证据；数字是否保留单位、窗口与范围；因果链是否夹带未标注假设；业务影响是否有运行证据；建议是否包含验证方式；故障状态是否与实际执行和验证相符。
